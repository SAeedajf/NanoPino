# Phase 1.4 — Central Public Site Context

## Status

Completed locally. Live deployment and browser verification were not executed in this phase.

## Problem

The public home, content and taxonomy actions repeated site_id=1 and locale=fa. The duplication made future multi-site or multi-locale support unsafe because one route could silently use a different scope from another.

## Implementation

- Added PublicSiteContext as the single validated runtime context for public routes.
- Added explicit Pinoox app configuration under public.site_id and public.locale.
- Public home, content and taxonomy queries now consume the context.
- Invalid site IDs or locale values fail closed and are converted by the existing public error boundary into a safe response.
- Existing defaults remain backward-compatible for the current single-site Persian installation.
- Release metadata was refreshed after the app configuration change.

## Validation

- PHP syntax validation passed for the changed runtime files.
- PHP runtime suite: 55 passed, 0 failed.
- Admin contract suite: 165 passed, 0 failed.
- Dist verification: 62 production assets verified; no root-domain /assets/ references.
- Live Pinoox database/browser validation: Not executed.

## Remaining risk

This phase centralizes configuration but does not yet select a site by host/domain. Multi-site routing still requires a trusted host-to-site resolver before public context can be selected dynamically per request.
