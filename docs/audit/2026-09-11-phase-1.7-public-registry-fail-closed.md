# Phase 1.7 — Fail-Closed Managed Public Registry

## Status

Completed locally. Live deployment and browser verification were not executed in this phase.

## Problem

The managed public host registry was read inside a broad fallback catch. A malformed stored value could therefore be ignored and replaced with the file-level map, hiding configuration corruption and weakening the domain boundary.

## Implementation

- Removed the broad fallback around managed registry validation.
- Missing settings records still use the app-level compatibility map.
- Database/read failures and malformed managed values now propagate to the existing public safe error boundary.
- The registry validator remains shared by Settings writes and runtime resolution.
- Added regression coverage for the fail-closed behavior.

## Validation

- PHP syntax validation passed.
- PHP runtime suite: 58 passed, 0 failed.
- Admin contract suite: 168 tests expected after release metadata refresh.
- Dist verification: 62 production assets verified; no root-domain /assets/ references.
- Live Pinoox database/browser validation: Not executed.

## Remaining risk

The public host registry is now fail-closed, but the Settings API still exposes only the current site scope. Full multi-site administration needs a separately authorized site catalog and scope selector.
