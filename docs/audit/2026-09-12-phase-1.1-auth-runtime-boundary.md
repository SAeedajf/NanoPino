# Phase 1.1 — Authentication and Runtime Boundary

## Scope

This phase separates authentication failures from authorization failures at the
mounted NanoPino boundary and keeps the browser/runtime clients fail-closed when
the actor is anonymous or the authenticated identity was not hydrated.

## Delivered

- Mounted permission denials now return HTTP `401 AUTHENTICATION_REQUIRED` for
  anonymous requests and HTTP `403 ACCESS_DENIED` for authenticated users that
  lack the requested capability.
- Non-API denials expose a non-cacheable response with
  `X-CMS-Auth-State: anonymous|authenticated` for host-shell integration.
- The admin boot payload exposes an explicit `authState` value.
- Vue and native runtime permission affordances fail closed for an explicit
  anonymous state or an authenticated state without a hydrated identity.
- The shared API response parser localizes the standard auth/permission errors,
  marks authentication failures, and emits `pinoox-cms:auth-required` without
  exposing server response details.
