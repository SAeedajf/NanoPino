# Phase 1.1 — Operational Taxonomy Management

Status: **Completed locally**

## Scope

The taxonomy layer was previously usable by content pickers, but its mutation lifecycle was not exposed as a complete admin capability. This phase makes registered categories and tags manageable through the service, runtime API, and Admin UI.

## Delivered

- `TaxonomyService` now supports create, update, and delete with site-scoped authorization, validation, unique slugs, hierarchy-cycle protection, audit events, and safe deletion.
- Repository adapters support immutable term updates and reject deletion of assigned or parent terms.
- Runtime routes and the versioned taxonomy contract expose `POST`, `PATCH`, and `DELETE` term operations.
- The Admin Panel now has a real `/taxonomies` surface for search, pagination, create, edit, and delete. Read-only actors see the data but cannot mutate it.
- Persian and English Admin copy includes the new surface.
