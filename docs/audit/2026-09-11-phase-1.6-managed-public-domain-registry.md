# Phase 1.6 — Managed Public Domain Registry

## Status

Completed locally. Live deployment and browser verification were not executed in this phase.

## Problem

Public host routing was safe but could only be changed in app.php. Site administrators had no CMS setting to manage domains, and a domain change required a file deployment.

## Implementation

- Added the site-scoped JSON setting site.public_hosts.
- The existing Settings API exposes the setting with settings.manage write permission, optimistic version checks and audit logging.
- The setting validator reuses PublicSiteContext, so malformed hosts, wildcard hosts, invalid site IDs, invalid locales and normalized duplicates are rejected before persistence.
- PublicSiteContext reads the managed registry when a setting record exists and keeps the app-level map as an installation-migration fallback.
- Empty managed values intentionally disable the file-level host map for the current site.

## Remaining risk

The current Settings API still exposes site scope as site 1 only. The registry is therefore operational for the current single-site installation; full multi-site administration requires widening the trusted site selector and its authorization scope in a separate phase.
